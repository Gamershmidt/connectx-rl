# ConnectX: внешние результаты и следующие эксперименты

Обзор от 2026-11-09. Это изучение источников и план; новые эксперименты не запускались.
Чужие результаты ниже не воспроизведены в нашем окружении.

## Какие метрики сравниваются

В ConnectX данные для RL создаются во время партий в игровой среде.

- **Наш локальный score:** `(wins + 0.5 * draws) / games`; macro score — среднее по четырём фиксированным соперникам. Текущий DQN: 0.29294 ± 0.01542 по пяти сидам; против random — 0.915, tactical — 0.214, lookahead — 0.000, kaggle_negamax — 0.04275.
- **Win rate:** `wins / games`; ничьи не дают половину балла. Результат зависит от соперника, стороны, дебютов и количества партий.
- **Kaggle skill rating:** динамический рейтинг по матчам между сабмишенами. Официальное описание задаёт оценку силы μ и неопределённость σ, начальный μ=600 и последующее обновление по результатам матчей. Рейтинг нельзя переводить в наш macro score простой формулой. [Правила оценки Kaggle](https://www.kaggle.com/competitions/connectx).
- **Training reward:** зависит от функции награды; при reward shaping не является прямой мерой качества игры.

## Что следует из наших результатов

Baseline обучался только против random и пропускает 86.56% учитываемых возможностей заблокировать угрозу. Проверяемая гипотеза: разнообразие тренировочных соперников важнее увеличения сети для освоения защиты. Это интерпретация, а не установленная причина слабой игры.

В [журнале подбора](hparam_search.md) уже записаны CNN-пробы: CNN 2×32 + FC128 и вариант 2×64. Они остановлены на 2–6 тыс. эпизодов; указано замедление примерно в 20 раз. Их нельзя считать окончательным отрицательным результатом CNN: обучение короче, чем у финального MLP, а исходные временные логи не сохранены в проекте.

## Предлагаемое сравнение

1. **MLP + random** — существующая точка отсчёта.
2. **MLP + random/tactical 50/50** — изолированная проверка состава тренировочного пула, без смены сети и награды.
3. **Небольшая CNN + тот же random/tactical 50/50** — сравнение архитектуры с пунктом 2. До полного запуска измерить скорость и зафиксировать бюджет. Отдельно показать качество при одинаковом количестве переходов и затраты времени.
4. **MaskablePPO + тот же пул** — следующая, более дорогая проверка алгоритма обучения, если первые сравнения не дают ответа. PPO — алгоритм обучения; MLP/CNN — архитектуры, их эффекты следует разделять.

Для первичного отбора использовать один seed только на validation; подтверждение выбранного варианта — минимум три общих с baseline seed. Основные показатели: macro score, score по каждому сопернику и стороне, доля пропущенных побед/блоков, нелегальные ходы, время обучения и инференса. Заранее зафиксировать критерий выбора и предел числа вариантов.

Текущий test уже просмотрен и использован для формулирования новых гипотез. Его результаты сохраняются как первоначальный эксперимент. Перед новой серией зафиксировать дополнительный финальный набор RNG seeds и дебютов, не использовать его при разработке, а после выбора конфигурации оценить на нём **и baseline, и новую модель**. Это проверяет устойчивость к новым партиям при известном пуле соперников; обобщение на новые семейства соперников требует отдельного holdout.

Идеи и любой заимствованный код нужно явно атрибутировать в README согласно условиям ДЗ. Изучение источников само по себе не подтверждает воспроизведение их результатов.
